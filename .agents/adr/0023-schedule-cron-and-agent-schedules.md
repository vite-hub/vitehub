# Schedule Cron and Agent Schedules

ViteHub schedule behavior belongs in the singular `@vitehub/schedule` package, with cron-only Static Schedule Definitions declared through `defineSchedule`, recurring cron Runtime Schedules managed through the `schedules` Runtime Helper, and a `schedule()` Agent Capability helper that can declare inline Agent Schedules or expose scoped read/edit schedule tools. Static schedule files and inline Agent Schedules are authoring forms over the same internal Static Schedule Definition model; Runtime Schedules are dynamic cron timing data over runtime-eligible static targets.

Provider wake mechanisms such as Cloudflare Cron Triggers, Durable Object alarms, Vercel Cron routes, or local timers stay behind provider integrations rather than becoming app-facing Schedule vocabulary. The first version intentionally excludes interval-style `every`, one-time/deferred schedules, timezone support beyond UTC cron, standalone schedule target definitions, and user-configurable retry, overlap, dedupe, or backfill behavior so Schedule does not absorb Queue or Workflow scope before those boundaries are explicit.

Static schedule ids default from schedule file names and can be overridden. A `defineSchedule` handler is not reusable by Runtime Schedules or Schedule Capability tools unless it opts into runtime reuse with `allowRuntimeSchedules`; Schedule Capability access is further constrained by its own policy and typed target allowlist. Inline Agent Schedules target the owning Agent, start independent Agent Invocations with schedule-owned input metadata, and do not require or write Chat History by default.
