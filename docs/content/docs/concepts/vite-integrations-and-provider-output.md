A Vite Integration connects a package to Vite development and build behavior. Provider Output is the host material that the integration generates, such as routes, functions, bindings, workers, crons, or runtime files.

The integration is the configuration entry point. Provider Output is the generated result to inspect. Application code uses the package's Runtime Helper instead of importing generated internals.

## Configure the integration

```ts [vite.config.ts]
import { hubAgent } from '@vite-hub/agent/vite'
import { hubKv } from '@vite-hub/kv/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [
    hubKv(),
    hubAgent(),
  ],
})
```

Put integration options in `vite.config.ts` when they affect discovery, generated files, provider bindings, or deployment output. Put options beside a Definition when they describe one named declaration.

## Use Provider Output as build evidence

Inspect generated output when you need to verify routes, bindings, or host wiring. Import it from application code only when the package documents a stable path such as `#vitehub/env/server`.

| Need | Surface |
| --- | --- |
| Development and build wiring | The package Vite Integration. |
| One named declaration | A Definition file. |
| Host deployment material | Provider Output generated by the integration. |
| Server code access | A Runtime Helper or documented stable import. |

Read [Definition discovery](/docs/concepts/definitions-and-discovery), [Runtime Helpers and stable imports](/docs/concepts/runtime-helpers-and-stable-imports), and [Provider Output](/docs/reference/provider-output) for the adjacent boundaries.
