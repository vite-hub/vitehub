A Vite Integration connects package declarations to Vite development and build behavior. Provider Output is the generated host material that makes those declarations run, such as routes, functions, bindings, workers, crons, or runtime files.

ViteHub keeps normal application authoring on the Vite Integration and stable package imports. Provider Output proves what will run on a host; it is not automatically an application API.

## Configure the integration

```ts [vite.config.ts]
import { hubAgent } from '@vite-hub/agent/vite'
import { hubKv } from '@vite-hub/kv/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [
    hubKv(),
    hubAgent(),
  ],
})
```

Put integration options in `vite.config.ts` when they affect discovery, generated files, provider bindings, or deployment output. Put Definition options beside the Definition when they travel with one named declaration.

## Provider Output is evidence, not a stable import

Inspect generated output when you need to verify routes, bindings, or host wiring. Import it from application code only when the package documents a stable path such as `#vitehub/env/server`.

| You need | Use |
| --- | --- |
| Build and development wiring | The package Vite Integration. |
| One named runtime declaration | A Definition file. |
| Host-specific deployment material | Provider Output generated by the integration. |
| Server code access | A Runtime Helper or documented stable import. |

Read [Definition discovery](/docs/concepts/definitions-and-discovery), [Runtime Helpers and stable imports](/docs/concepts/runtime-helpers-and-stable-imports), and [Provider Output](/docs/reference/provider-output) for the adjacent boundaries.
