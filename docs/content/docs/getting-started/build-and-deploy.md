Start with [Installation](/docs/getting-started/installation) and run one route
locally before you pick production resources. ViteHub turns on only the
features you select.

## Choose your framework and host

Use the [Nuxt module](/docs/frameworks-hosts/nuxt) in a Nuxt app, or
[Nitro and Vite](/docs/frameworks-hosts/nitro-unjs) when you configure the
server build yourself. The [overview](/docs/frameworks-hosts) explains hosts
and the default provider for each feature.

To deploy, open the guide for
[Cloudflare](/docs/frameworks-hosts/cloudflare),
[Vercel](/docs/frameworks-hosts/vercel),
[Netlify](/docs/frameworks-hosts/netlify),
[Deno](/docs/frameworks-hosts/deno), or
[Node](/docs/frameworks-hosts/node-self-hosted).
Read [Production](/docs/frameworks-hosts/production) before you connect real
resources.

## Inspect your app while you build

The [development tools](/docs/development) show the Definitions ViteHub finds
and the output it generates. Use the [CLI](/docs/development/cli) or the
[Console](/docs/development/console) at [console.vitehub.dev](https://console.vitehub.dev), which opens your deployed apps from one place.
Read
[Troubleshooting](/docs/development/troubleshooting) when an integration or
provider fails.

## Check the exact contract

The [shared reference](/docs/reference) covers configuration, import paths,
file conventions, runtime events, and diagnostics. For one feature's API, open
its Server API page in the left rail.
