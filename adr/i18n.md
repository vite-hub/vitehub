# @vite-hub/i18n decisions

Each entry records a decision that the code cannot show. See [README.md](README.md) for the format.

## i18n build and runtime ordering

`Symbol.for("vite-hub.i18n.state")`, `splitRuntimeImports`, `bindVueMessages`, `assertWorkspaceDefined`, `renderChunk`, `message extraction`, `request hook` in `packages/i18n/src/runtime.ts`, `packages/i18n/src/macros.ts`, `packages/i18n/src/vite.ts`, `packages/i18n/src/server.ts`.

**Context:** Lingui drops macro-package imports; build order browser then server; Nitro awaits hooks.

**Decision:** Global realm state; move runtime imports aside before Lingui; check Workspaces in buildStart with enforce post; collect browser ids for the server; extract from disk; return the revision load from the hook.

**Consequences:** The plugin and pass order is load-bearing.

## A save without an editor reaches Diglot's review functions as an empty reviewer

`applyReview`, `nextRecord` in `packages/i18n/src/server.ts`.

**Context:** `save()` lets the caller leave out the editor, but Diglot 0.2.1 `ReviewOptions` types `by` as a required string (danielroe/diglot: no optional reviewer).

**Decision:** Pass the editor or an empty string to `editRecord`, `rejectRecord` and `verifyRecord`, then store `by: undefined` on the record when it is empty.

**Consequences:** Requiring an editor in `save()` would change the public API. Remove the `|| undefined` once Diglot takes an optional reviewer.

## Clearing a translation rejects the source text

`nextRecord` in `packages/i18n/src/server.ts`.

**Context:** Diglot refuses empty text and has no cleared state (danielroe/diglot: no way to clear a translation).

**Decision:** An empty translation becomes a record whose text is the source and whose review is `rejected`. Readers treat a rejected record as missing, so the page shows the source fallback.

**Consequences:** `isVisibleRecord` and the lineage must keep treating rejected records as missing. Replace this with Diglot's cleared state once it has one.

## i18n checks Workspaces through the Workspace plugin's untyped api

`assertWorkspaceDefined` in `packages/i18n/src/vite.ts`.

**Context:** `@vite-hub/i18n` does not depend on `@vite-hub/workspace`, and the Workspace package exports no typed lookup of its plugin api.

**Decision:** Find the plugin named `@vite-hub/workspace/vite` and call `api.getWorkspaces()` when it exists.

**Consequences:** Renaming the Workspace plugin or `getWorkspaces` silently turns every `i18n.workspace` into `I18N_UNKNOWN_WORKSPACE`. Replace this with a typed lookup once the Workspace package exports one.

## Message segments are cast to Diglot's SegmentKind

`diglotSegment` in `packages/i18n/src/record-format.ts`, `records test manifest` in `packages/i18n/test/records.test.ts`.

**Context:** Diglot 0.2.1 and 0.2.2 type `SegmentKind` without a `message` kind (danielroe/diglot). `validate()` only compares the kind with single-line and code-comment kinds, and `diglot validate` accepts the JSON manifest.

**Decision:** Cast `"message"` through `string` to `SegmentKind` in both places.

**Consequences:** A Diglot release that branches on unknown kinds would validate messages differently. Remove both casts once Diglot types the `message` kind.
