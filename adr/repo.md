# Repository decisions

Each entry records a decision that the code cannot show. See [README.md](README.md) for the format.

## Code comments are banned, with a per-file ratchet

`vitehub/no-comments` in `scripts/lint/comments.mjs`, `scripts/lint/comment-baseline`, `vite.config.ts`.

**Context:** Most comments repeated the code, went stale, or excused a workaround that other code then copied. Agents write most ViteHub code and read comments as instructions, so a wrong comment spreads. The repository had about 24,000 such comments when the rule landed, too many for one pull request.

**Decision:** The `vitehub/no-comments` Oxlint JS plugin rule reports every comment that no tool reads. `scripts/lint/comment-baseline/<area>.json` stores the count per file at the time the rule landed. A file passes while its count is at or below the baseline. A decision goes into `adr/`, and a workaround gets an issue. `/delete-comment` (`.agents/skills/delete-comment`) is the process.

**Consequences:** A new file can have no banned comments. An edit can only keep or lower a file's count. Run `node scripts/lint/update-comment-baseline.mjs` after a deletion so the baseline goes down; a higher count must never be written to the baseline by hand.

## The comment rule keeps comments that a tool reads

`directive`, `catalogGroup`, `diagnosticCode`, `jsTypes`, `keepApiDoc` in `scripts/lint/comments.mjs`.

**Context:** Some comments are input to a tool, not prose. Deleting them changes behavior or breaks a check.

**Decision:** The rule allows: compiler, linter, formatter, and coverage directives; bundler annotations such as `#__PURE__` and `@vite-ignore`; triple-slash references; license comments; `// SAFETY:` comments and the `//` lines that directly continue them, which Vite Doctor reads; `// provider-message-match:` markers, which `test/provider-message-matching.test.ts` reads; `/* @vitehub-<name> */` import markers, which ViteHub transforms find and rewrite, such as `/* @vitehub-env */` (the Env plugin in `packages/env/src/vite.ts`) and `/* @vitehub-schedule-registry */` (the Schedule plugin); `// Generated by` headers that generators write; a one-sentence `// <Group> errors.` comment directly above a diagnostic code key, which `commentGroup()` in `docs/modules/diagnostics/catalog.ts` reads as the docs sidebar group; typed JSDoc (`@type {`, `@param {`) that gives a JavaScript file its types; and JSDoc on exported declarations and their members in `packages/*/src`, which ships in `.d.ts` files as the public API docs. Files under `fixtures/` folders are not checked.

**Consequences:** A new tool that reads comments needs an exemption in `scripts/lint/comments.mjs` before its comments can stay. Moving the docs group into catalog data would let the `catalogGroup` exemption go.

## One comment baseline file per area

`areaOf` in `scripts/lint/comments.mjs`, `scripts/lint/update-comment-baseline.mjs`.

**Context:** Many pull requests run in parallel. One baseline file would conflict on almost every pull request that deletes comments.

**Decision:** `areaOf()` maps a file to `packages-<package>`, its top-level folder, or `root`, and the baseline has one JSON file per area.

**Consequences:** Two pull requests conflict on the baseline only when they delete comments in the same area.

## Published diagnostic codes are stable and retired codes are never reused

`each package's defineErrors/defineDiagnostics catalog` in `packages/browser/src/error-diagnostics.ts`, `packages/browser/src/run-errors.ts`, `packages/bundle/src/diagnostics.ts`, `packages/channels/src/error-diagnostics.ts`, `packages/choices/src/diagnostics.ts`, `packages/email/src/error-diagnostics.ts`, `packages/env/src/error-diagnostics.ts`, `packages/env/src/seal-value.ts`, `packages/forge/src/error-diagnostics.ts`, `packages/forge/src/errors.ts`, `packages/gateways/src/diagnostics.ts`, `packages/i18n/src/errors.ts`, `packages/markdown-template/src/error-diagnostics.ts`, `packages/mcp/src/error-diagnostics.ts`, `packages/shell/src/error-diagnostics.ts`, `packages/web-container/src/error-diagnostics.ts`, `packages/webhooks/src/errors.ts`.

**Context:** The docs build writes one page per code, and error messages link to it.

**Decision:** Never rename or reuse a code. Retired codes stay reserved.

**Consequences:** The retired-code lists existed only in these comments; put them in data or the ADR.

## Knip config adds only patterns that match, and derives package entries from manifests and Vite configs

`matching`, `toSource`, `importPaths`, `viteConfigEntries`, `bundledInternal` in `knip.config.ts`.

**Context:** Knip prints a hint for an entry that matches no file and for an unneeded ignore. Knip maps dist to src only from a tsconfig outDir, which packages do not set. The vite-plus plugin reads only run.tasks. Packages bundle @vite-hub/internal with alwaysBundle.

**Decision:** Every entry list goes through matching(), so a new Knip hint means the config is out of date. Package entries come from package.json exports/imports/bin mapped from ./dist to src, plus source paths named in vite.config.ts and *.vite.config.ts. Each package that bundles internal declares the internal modules' imports, listed in bundledInternal.

**Consequences:** Adding a pattern without matching() hides out-of-date config. Setting outDir or changing the dist layout breaks toSource. A new internal import used by a bundling package must be declared by that package.

## Knip roots are only convention-loaded files; optional peers and public exports are not checked

`viteHubAppEntries`, `config.include`, `config.exclude` in `knip.config.ts`.

**Context:** ViteHub loads Nitro handlers and Definitions by file convention (docs/content/docs/reference/file-conventions.md). Packages import optional peers when an app uses a feature. exports/types/duplicates would report every package's public API.

**Decision:** Only convention-loaded server files are entries; ordinary helpers must be reached through an import. Knip runs files, dependencies, unlisted, unresolved, binaries and catalog, and excludes optionalPeerDependencies.

**Consequences:** Widening viteHubAppEntries hides unused helpers. Turning on exports or optional peers floods the report with intended public API.

## The docs app depends on @nuxt/icon to pin the copy that Nuxt UI loads

`workspaces.docs.ignoreDependencies` in `knip.config.ts`, `docs/package.json`.

**Context:** Nuxt UI installs @nuxt/icon by name, and Nuxt resolves it from the app first.

**Decision:** docs lists @nuxt/icon itself so the app controls which copy loads.

**Consequences:** Removing the 'unused' dependency lets Nuxt UI's own range choose the copy.

## check-ci-inputs keeps only the CI input rules that zizmor and actionlint do not cover

`module`, `exactPackage`, `dockerDigest`, `executorCall` in `.github/scripts/check-ci-inputs.mjs`.

**Context:** The workflow-lint job runs zizmor and actionlint. zizmor's adhoc-packages audit does not read executors, and unpinned-uses skips docker:// references.

**Decision:** The script checks two rules only: transient executors (npx, pnpm dlx, vp dlx, ...) name an exact version, and docker:// actions use a sha256 digest. It reads plain text and does not model shell semantics.

**Consequences:** Rules that zizmor already covers do not belong here. The scan catches accidents, not hidden calls.

## All @ui-sdk packages resolve to one version, and dropping a ui-sdk patch needs a check

`versionFailures`, `droppedPatches` in `.github/scripts/check-ui-sdk.mjs`.

**Context:** @ui-sdk/vue calls into @ui-sdk/core, and the kit build inlines core's web.css. ViteHub patches both packages through patchedDependencies.

**Decision:** Fail when the lockfile has more than one @ui-sdk version. Warn when a change drops a ui-sdk patch, because the patch holds fixes that npm may not have.

**Consequences:** Bumping one @ui-sdk package alone ships parts and styles that do not match.

## npm trusted publishing: claim new packages with a placeholder, and refresh expired links

`module`, `trustApi`, `publishesFromRelease`, `ownedPackages` in `.github/scripts/claim-npm-packages.mjs`.

**Context:** npm links a trusted publisher only to a package that exists. Links expire without the CLI saying so (release fails with ENEEDAUTH). `npm trust` holds the sign-in link back with --json. The registry answers 404 for a few minutes after a first publish. npm allows one trusted publisher change every 2 seconds. createPackage is the publish permission; createStagedPackage cannot publish.

**Decision:** Publish 0.0.0-claim under the claim dist-tag for new packages, call the trust API directly with web OTP, read owned packages from `npm access list`, accept configs with no environment or npm-release plus createPackage, and with --replace refresh links of packages whose version is not on npm yet. Space trust changes 2 s apart.

**Consequences:** Using `npm trust --json`, the registry 404 check alone, or faster calls breaks the claim run; ignoring expiry leaves the release with ENEEDAUTH.

## Live-smoke teardown order and R2 key encoding follow Cloudflare API rules

`teardownCloudflare`, `emptyR2Bucket` in `.github/scripts/live-smoke-teardown.mjs`.

**Context:** Cloudflare refuses to delete a Worker that consumes a Queue (10064) and a Queue that a Worker binds (11005). R2 object paths need literal '/' separators.

**Decision:** Delete Queue consumers first, then Workers, then Queues. Encode each R2 key segment and join with '/'.

**Consequences:** Reordering steps or encoding the whole key makes teardown fail and leaves scratch resources.

## Preview peers accept the npm range or the preview version

`writePreviewManifests`, `previewVersion` in `.github/scripts/preview-packages.mjs`.

**Context:** pkg.pr.new rewrites dependencies to preview URLs but not peers. pnpm 10/11 install an optional peer found elsewhere in the graph from npm. npm stops when it cannot fetch a peer version.

**Decision:** Each ViteHub peer becomes `<packed npm range> || 0.0.0-preview-<sha7>`. Apps moving to a preview run `pnpm update vite-hub "@vite-hub/*"`.

**Consequences:** Dropping the preview version mixes npm releases into preview graphs; dropping the npm range makes npm installs fail.

## A release PR holds only uppt's version commit

`check-release-candidate (workspace range check)`, `checks uppt's release commit and dispatches checks without adding a commit`, `release candidate check (fixture workspace)` in `.github/scripts/check-release-candidate.mjs`, `test/release-pr-workflow.test.ts`.

**Context:** uppt rebuilds a release branch only when it holds uppt's commit alone.

**Decision:** The release workflow never commits, bumps or pushes. Internal ranges use workspace: or *, and the release workflow pins them to exact versions when it packs.

**Consequences:** An extra commit or a pinned internal range stops uppt from rebuilding the release branch.

## Release and preview builds run the package filter with --no-cache directly

`run.tasks.build` in `vite.config.ts`, `.github/workflows/release.yml`, `.github/workflows/pkg-pr-new.yml`.

**Context:** The root `build` task runs a nested `vp run --cache --filter ./packages/* build`. An outer --no-cache does not reach the nested run.

**Decision:** Release, preview and CI publishing call `vp run --no-cache --filter "./packages/*" build`, not `vp run build`.

**Consequences:** Switching publishing to `vp run --no-cache build` can publish a cached build.

## Root Vitest compiles every file with the root tsconfig

`defineConfig tsconfig` in `vitest.config.ts`.

**Context:** Root contracts import files from apps whose tsconfig extends a generated file (docs/tsconfig.json extends docs/.nuxt/tsconfig.json).

**Decision:** Set tsconfig: "tsconfig.json" so root contracts run in a fresh checkout before docs are prepared.

**Consequences:** Removing it makes root tests fail on a fresh checkout until nuxi prepare runs.

## consumer-check passes '.' to rg explicitly

`searchRoot` in `scripts/consumer-check.mjs`.

**Context:** With no path, rg searches stdin when stdin is not a terminal.

**Decision:** Always pass '.' as the search path.

**Consequences:** Dropping the 'redundant' path makes the search read stdin and miss every hit when run from a script or CI.

## Test harnesses fail on missing coverage instead of skipping silently

`runCloudflare`, `runVercel`, `providerEnabled`, `readOutputFile` in `test/local/local.mjs`, `test/output/helpers.ts`.

**Context:** Local and output suites can run without some providers or outputs.

**Decision:** A suite that cannot run logs an EXCEPTION line. Missing Provider Output throws. Only VITEHUB_OUTPUT_PROVIDER narrows the providers.

**Consequences:** Turning these into skipIf or describe.skip makes a skipped run look like a pass.

## Harnesses stop whole process groups and wait until they are gone

`stopChild`, `hasLiveGroupMember`, `manageChild`, `withDevServer`, `stopProcessGroup` in `test/local/process.mjs`, `test/consumer/vite-hub.test.ts`.

**Context:** Children start detached through package managers or wrappers; the leader exits before the server does.

**Decision:** Signal the negative pid, SIGKILL survivors after the leader closed, poll /proc tolerating ENOENT/ESRCH, keep SIGINT/SIGTERM handlers until children are reaped then re-raise. Detect dev-server readiness from the log, not HTTP.

**Consequences:** Killing only the leader, or removing the app directory when the leader exits, leaks processes or fails with ENOTEMPTY.

## Consumer fixtures install ViteHub only from packed tarballs

`fixturePackages`, `usePackedPeerManifests`, `installApp`, `importPackageWithoutRootFallback`, `workspaceDependencyClosure` in `test/local/netlify-real-project.mjs`, `test/consumer/vite-hub.test.ts`, `test/consumer/public-package-exports.test.ts`.

**Context:** pnpm installs any overridden optional peer, resolves optional peer graphs from registry metadata, and looks up unpublished versions on npm.

**Decision:** Override only the packed closure of what the app requires, feed packed manifests through a .pnpmfile readPackage hook, keep the runtime closure when root dependencies are hidden, and assert no non-optional registry snapshot of a ViteHub package.

**Consequences:** Overriding every package installs unrelated optional peers; dropping the hook or closure makes tests use npm releases or fail on release branches. The 'Agent's Forge adapter' example may be stale.

## Consumer fixtures pin peers to the exact versions ViteHub packages publish (one Nitro copy)

`workspaceConfig`, `appDependencies` in `test/consumer/vite-hub.test.ts`, `test/multi-instance/run.mjs`.

**Context:** Two Nitro copies break Nuxt plus ViteHub apps, and strict peer installs reject other versions.

**Decision:** Fixtures set vue, nitro and nitro>h3 to the published peer versions; the multi-instance app uses the same framework pins as the packed Nuxt 5 tests.

**Consequences:** Bump the pins together across consumer tests and multi-instance run.mjs.

## The vite override to vite-plus-core needs vite-plus installed

`appDependencies` in `test/multi-instance/run.mjs`, `test/consumer/vite-hub.test.ts`.

**Context:** Fixtures override vite with npm:@voidzero-dev/vite-plus-core.

**Decision:** The app also depends on vite-plus at the same version.

## Multi-instance build reads backend env; REDIS_URL only in Redis mode

`runtimeConfig`, `vitehub.blob`, `vitehub.kv`, `baseEnv`, `startBackends`, `buildApp`, `boot check` in `test/multi-instance/app/nuxt.config.ts`, `test/multi-instance/run.mjs`, `test/multi-instance/checks.mjs`.

**Context:** nuxt.config reads REDIS_URL and MULTI_INSTANCE_SHARED_BLOB_DIR at build time; KV never infers Redis.

**Decision:** run.mjs deletes REDIS_URL from baseEnv without Redis, passes backend env to the build, and /api/health exposes multiInstanceBuildRedis for the boot check.

**Consequences:** A shell REDIS_URL leaking in, or a reused --app build from another mode, makes the without-redis run test Redis.

## Multi-instance checks use an independent oracle and fixed timing

`record`, `main`, `appDependencies`, `queue-once`, `rate-limit-shared`, `queue-failover` in `test/multi-instance/app/server/oracle.ts`, `test/multi-instance/run.mjs`, `test/multi-instance/checks.mjs`.

**Context:** Checks must observe primitives across 3 instances without trusting them.

**Decision:** oracle_events uses a separate postgres client; instances start concurrently; ws, y-websocket and yjs stay in app deps; queue spread is not asserted; rate-limit waits for an early second; queue-failover runs last with a 5 s delay.

**Consequences:** Reordering checks, removing the 'unused' deps, starting instances one by one, or asserting spread breaks or weakens the harness.

## Declaration contract checks only the packed package's own files

`isPackageDeclarationFile`, `declarationDiagnostics` in `test/consumer/declaration-diagnostics.ts`.

**Context:** Checking every dependency declaration is slow and reports third-party errors.

**Decision:** Collect per-file syntactic and semantic diagnostics only for package files, merged in getPreEmitDiagnostics order.

**Consequences:** Switching to getPreEmitDiagnostics reports dependency errors and slows the contract.

## Package typecheck uses tsrs with a fallback only on unsupported hosts

`packageTypecheckCompiler` in `test/package-typecheck.mjs`.

**Context:** tsrs ships native packages for some platforms only.

**Decision:** Fall back to typescript-native only when no @tsrs/<platform>-<arch> optional dependency exists; never on errors.

**Consequences:** A catch-and-fallback would hide broken tsrs installs on supported hosts.

## run-package-task selection rules and CI contract

`BUILD_MAX_PARALLEL`, `OUTSIDE_TEST_INPUTS`, `NO_PACKAGE_TEST_INPUTS`, `selectPackages`, `executePackage` in `test/run-package-task.mjs`.

## Libraries the app also uses are peers with ranges, so one copy installs

`installs one version of each AI SDK package with @vite-hub/agent`, `@vite-hub/%s takes comark, @comark/html, and comark-ui from the app`, `@vite-hub/%s takes Tiptap and Yjs from the app`, `declares peers that the app also installs as ranges that accept the app's copy`, `declares peer ranges that accept the versions that sibling packages depend on`, `keeps Cloudflare Worker declarations out of the vite-hub install` in `test/ai-sdk-single-copy.test.ts`, `test/comark-single-copy.test.ts`, `test/tiptap-single-copy.test.ts`, `test/contracts.test.ts`, `test/public-package-exports.test.ts`.

## Fixture process cleanup: process group on POSIX, taskkill tree on Windows

## Content playground translation pipeline
