# @vite-hub/mcp

The MCP server of a ViteHub app. Each file in `server/mcp/tools/` is one tool, each file in `server/mcp/prompts/` is one prompt, and each file in `server/mcp/resources/` is one resource. The server answers at `/mcp`. Apps install this package and import `vite-hub/mcp`. This README is the contract for ViteHub packages.

```ts [server/mcp/tools/add.ts]
import { defineMcpTool } from 'vite-hub/mcp'
import { z } from 'zod'

export default defineMcpTool({
  description: 'Add two numbers.',
  input: z.object({ a: z.number(), b: z.number() }),
  handler: ({ a, b }) => ({ sum: a + b }),
})
```

Turn it on with `vitehub({ auth: true, mcp: true })` and `mcpOAuth()` from `vite-hub/auth/mcp`, or with `vitehub({ mcp: { auth: false } })` to let anyone call every tool. User docs: [MCP server](https://vitehub.dev/docs/mcp).

## Contract

- The tool name is the file path below `mcp/tools/` without the extension. A name that MCP does not allow fails the build with `MCP_B0002`.
- `input` is a Standard Schema with a Standard JSON Schema (`~standard.jsonSchema`). `tools/list` shows its input JSON Schema, and the server validates the arguments with it before the handler runs. Invalid arguments are a tool error for protocol `2025-11-25`, or JSON-RPC `-32602` for `2025-06-18`.
- The handler gets `(input, { event, caller, elicit })`. A string is one text block. An object with a `content` array of blocks is the MCP result, with its `structuredContent`, `isError`, and `_meta`. Any other value is JSON text, and an object is also `structuredContent`.
- `_meta` of a tool is in its `tools/list` entry. `_meta` of a resource is in its `resources/list` and `resources/templates/list` entries and in the contents of a string or `Uint8Array` handler result. The server sends them as they are, so an MCP App sets `_meta.ui.resourceUri` on the tool and serves its HTML as a `ui://` resource with `mimeType: "text/html;profile=mcp-app"`.
- A thrown error with a 4xx `status` is a tool error with its message. Other errors are logged and the Agent reads `<name> failed on the server.`
- A prompt is the default export of `defineMcpPrompt()` in `server/mcp/prompts/<name>.ts`. Its `input` is an object Standard Schema with string fields. `prompts/list` shows each field as an argument, with its `description` and whether it is required. `prompts/get` checks the arguments, then runs `handler(input, { event, caller })`. A string is one user message, an array is the messages, and an object with `messages` is the result. Invalid arguments and a thrown 4xx error are JSON-RPC `-32602` with the message. Other errors are logged and answer `-32603`.
- A resource is the default export of `defineMcpResource()` in `server/mcp/resources/<name>.ts`. It has a fixed `uri`, or a `uriTemplate` where `{name}` matches one path segment and `{+name}` also matches `/`. `resources/list` shows the fixed resources and the entries of each template's `list()`. `resources/templates/list` shows the templates. `resources/read` runs `handler(uri, { event, caller, variables })` of the first resource with that `uri`, else of the first template that matches. A string is text, a `Uint8Array` is a base64 `blob`, and `{ contents }` is sent as it is. `undefined` and an unknown URI are JSON-RPC `-32002`.
- `initialize` advertises the `prompts` and `resources` capabilities only when the app has prompts or resources. Without them, their methods are JSON-RPC `-32601`.
- `server/mcp.ts` (or `.mts`, `.js`, `.mjs`) may default-export `defineMcpHooks({ resolveCaller, onToolCall })`. One module is allowed; two fail the build with `MCP_B0004`. `resolveCaller({ event, caller })` runs once per request, when the first tool, prompt, or resource handler runs, and its value is `caller` in the handlers. `initialize` and `tools/list` do not run it. A thrown 4xx error refuses the call with its message. The plugin writes `.vitehub/types/mcp.d.ts`, which sets `ViteHub.McpRegistry` so `caller` has the type that `resolveCaller` returns.
- `verifyToken({ event, token })` of the hooks runs when `auth` is on and the bearer token is not a valid access token of `mcpOAuth()`, such as an API key. The caller that it returns is the caller of the request, as for an access token. `undefined` answers `401` with `error="invalid_token"`. A request without a token never reaches it.
- `onToolCall({ name, input, caller, event, durationMs, result, error })` runs after each tool call whose arguments passed the input schema, before the answer is sent. `durationMs` is the time of the handler. `error` is what the handler or `resolveCaller` threw. An error of `onToolCall` is logged and does not change the result.
- `mcp.instructions` replaces the generic `instructions` of `initialize`. `mcp.serverInfo` sets `name`, `title`, `version`, `description`, `websiteUrl`, and `icons`. They default to the app name, the name, and `"1"`. An icon `src` or `websiteUrl` that starts with `/` becomes a URL on the request origin.
- `auth` defaults to `true`, in `hubMcp()` and in `vitehub({ mcp })`. Then the generated entry calls `verifyMcpRequest()` from `vite-hub/auth/mcp` for every request, answers `401` with `WWW-Authenticate: Bearer resource_metadata="<origin>/.well-known/oauth-protected-resource<route>"`, and serves `serveMcpOAuthDiscovery()` as middleware for `/.well-known/**`. `vitehub({ mcp })` without `auth` fails with `VITE_HUB_MCP_AUTH_MISSING`. Only an explicit `auth: false` serves every tool without sign-in.
- With `auth: "optional"`, the route also answers requests without a token. They list every tool and get the prompts and resources with `access: "public"`. A call to a tool with `access: "public"` runs with `caller: undefined`. A call to another tool returns `isError: true` with `_meta["mcp/www_authenticate"]`, an `insufficient_scope` challenge that names the protected resource metadata, as the OpenAI Apps SDK reads it. An invalid token still gets `401`. With `auth` on, `tools/list` shows each tool's `securitySchemes` on the tool and in its `_meta`: `[{ type: "noauth" }, { type: "oauth2" }]` for a public tool on an optional route, else `[{ type: "oauth2" }]`, with the tool's `scopes`. With `auth: true`, a signed-in caller without a tool's `scopes` does not see the tool, and a call gets `403` with an `insufficient_scope` challenge. With `auth: "optional"`, the call returns the `mcp/www_authenticate` tool error instead, as for a request without a token.
- With `publicRoute`, such as `mcp: { route: "/mcp/account", publicRoute: "/mcp" }`, a second server answers at that route with only the tools, prompts, and resources that set `access: "public"`. It needs no sign-in, never answers `401`, and the protected resource metadata does not name it. Most MCP clients do not sign in on a URL that answers without a token, so for them a server that has public tools and tools for a person needs two URLs. ChatGPT signs in from the challenge of `auth: "optional"` on one URL. `publicRoute` with `auth: false` or `"optional"` fails the build with `MCP_B0003`. A tool that sets `access` on a server without `publicRoute` or `auth: "optional"` fails `createMcpHandler()` with `MCP_R0001`, so the option never looks like it does something that it does not.
- With a non-root Nitro `baseURL` (including Nuxt `app.baseURL`), the MCP URL includes that base. Configure the `mcpOAuth()` resource with that full URL. OAuth discovery stays at the origin root through global middleware.
- The protocol is Streamable HTTP, revisions `2025-11-25` and `2025-06-18`, from `@vite-hub/internal/runtime/mcp-server`. It keeps no session state and has no `GET` stream. Every answer is JSON, except a `tools/call` whose handler elicits. The Console MCP uses the same server.
- `elicit(form, { message })` of a tool handler asks the person for the fields of a `defineForm()` form or a flat Standard Schema (MCP elicitation in form mode). It sends `toElicitation()` of `@vite-hub/forms` as `elicitation/create` on an SSE answer to the `tools/call`, waits for the client to POST its answer, and returns `readElicitation()`: `[undefined, { action: "accept", data }]`, `[undefined, { action: "decline" | "cancel" }]`, or `[error]` with the issue of each field. The answer is `cancel` after 10 minutes, when the client closes the stream, or when it cancels the tool call. An answer must use the same endpoint, session, and caller as the tool call.
- `initialize` gives a signed `Mcp-Session-Id` only to a client that declares the `elicitation` capability for form mode. The server checks the signature against the endpoint and caller without storing a session. Without a valid session ID, `elicit()` throws `MCP_ELICITATION_CLIENT_UNSUPPORTED`, which the Agent reads as a tool error.
- The waiting call lives in the memory of the server process, so the answer must reach the same process. That works on the dev server and in builds with the `node-server`, `node-middleware`, `bun`, and `deno-server` presets. In a build for any other preset, such as `cloudflare-module`, `vercel`, `netlify`, `deno-deploy`, or `node-cluster`, `elicit()` throws `MCP_ELICITATION_HOST_UNSUPPORTED`, which names the preset.
- `vitehub inspect definitions --kind mcp-tool` lists the tools. `--kind mcp-prompt` and `--kind mcp-resource` list the prompts and resources.

## Public imports

| Import | Use |
| --- | --- |
| `@vite-hub/mcp` | `defineMcpTool()`, `defineMcpPrompt()`, `defineMcpResource()`, `defineMcpHooks()`, and their types. Apps import it as `vite-hub/mcp`. |
| `@vite-hub/mcp/vite` | `hubMcp()`, the Vite plugin that `vitehub({ mcp })` adds, and `discoverMcpTools()`. |
| `@vite-hub/mcp/runtime` | `createMcpHandler()` and `createMcpOAuthDiscoveryHandler()`, which the generated server entry imports. |
| `@vite-hub/mcp/eval` | `runMcpEval()`, which scores the tool use of a model against the live tools of any MCP server. Apps import it as `vite-hub/mcp/eval`. It needs the optional peers `ai` and `@ai-sdk/mcp`. The other imports do not load them. |

## Tool-use evals

`runMcpEval({ server, cases, models, system?, check? })` connects to an MCP server over HTTP and reads its live `tools/list` and server instructions. Use the final endpoint URL, since the eval does not follow redirects. It sends each case prompt to a model with those tools, runs only the tools with `readOnlyHint: true`, and records every call. The checks of a case are `calls` (partial arguments: exact value, `~` substring, `re:` regular expression, dotted keys), `notCalls`, `maxCalls`, `finalTextMust`, and `finalTextMustNot`. Each case runs 2 samples, plus a 3rd when the first two do not agree, and fails at a pass rate of 0.5 or less. The flags are `--model`, `--case`, `--samples`, `--dry-run`, `--max-tokens`, `--out`, and `--baseline`. The run writes `results.jsonl`, `tools.json`, `run.json`, and `summary.md`, and exits with code `1` when a case fails, has only errors, or does not finish within the token budget. `run.json` has the surface hash (sha256 of the tools and the server instructions), a hash of each case, the pass rates, and the token totals. Commit it and pass it to `--baseline`: a model run shows the delta and flags regressions for unchanged cases. With `--dry-run --baseline`, the eval reports surface and case changes alongside validation errors and exits with code `1` if it finds any, with no model call. `@ai-sdk/mcp` adds `additionalProperties: false` to each input schema that the model sees. See [MCP tool-use evals](https://vitehub.dev/docs/mcp/evals).
